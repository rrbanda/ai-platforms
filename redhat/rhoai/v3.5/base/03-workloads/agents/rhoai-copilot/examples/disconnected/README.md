# Disconnected RHOAI Reference Examples

Captured YAML from verified end-to-end disconnected deployments. These are **read-only reference files** — compare your customized output against them to validate correctness.

Do NOT apply these directly to your cluster. The registry URLs, catalog digests, and CatalogSource names are specific to the environment where they were captured.

## rhoai-3.4.2-ocp-4.20.30/

Captured from a verified deployment on OpenShift 4.20.30 with RHOAI 3.4.2.
Source: [rh-aiservices-bu/disconnected-rhoai](https://github.com/rh-aiservices-bu/disconnected-rhoai)

| File | What It Is |
|------|-----------|
| `imageset-config-rhoai.yaml` | ImageSetConfiguration with digest-pinned catalogs and 63 additionalImages |
| `operators.yaml` | Namespace + OperatorGroup + Subscription for NFD, GPU, cert-manager, RHOAI |
| `dscinitialization.yaml` | DSCInitialization with real mirror CA in customCABundle |
| `datasciencecluster.yaml` | DataScienceCluster v2 API with all 14 components explicit |
| `idms-oc-mirror.yaml` | ImageDigestMirrorSet generated by oc-mirror v2 |
| `itms-oc-mirror.yaml` | ImageTagMirrorSet generated by oc-mirror v2 |
| `cs-redhat-operator-index-*.yaml` | CatalogSource for mirrored Red Hat operator catalog |
| `cs-certified-operator-index-*.yaml` | CatalogSource for mirrored certified operator catalog |

## Using These for Comparison

After running `oc-mirror --v2` on your environment, compare your generated files:

```bash
diff your-idms.yaml examples/disconnected/rhoai-3.4.2-ocp-4.20.30/idms-oc-mirror.yaml
```

The structure should match even though registry URLs and digests differ.
