Automated Setup Script

What the script creates

The setup-demo-namespace.sh script performs all cluster-admin operations in one run:

# Usage (run as cluster-admin):
./setup-demo-namespace.sh <namespace> <username>

# Example:
./setup-demo-namespace.sh spark-kueue-demo user1

The script creates:

ResourceNameDetails
Namespace<namespace>The test namespace
ResourceFlavordefault-flavorDefault node pool
ClusterQueuespark-cq8 CPU / 32Gi quota (for TC-1, TC-2, TC-5, TC-7)
ClusterQueuespark-cq-6cpu6 CPU / 32Gi quota (for TC-4 auto-queuing)
LocalQueuespark-lqPoints to spark-cq
LocalQueuespark-lq-6cpuPoints to spark-cq-6cpu
RoleBindingspark-demo-adminClusterRole admin in namespace
ClusterRolekueue-cq-viewerRead-only: get/list/watch ClusterQueues, ResourceFlavors
ClusterRoleBindingspark-demo-cq-viewer-<user>Binds user to kueue-cq-viewer
Two ClusterQueues: The script creates both spark-cq (8 CPU) and spark-cq-6cpu (6 CPU) so the namespace user never needs to patch ClusterQueue quota during the demo. For TC-4, reference spark-lq-6cpu in the SparkApplication label instead of patching.

Manual RBAC Setup

If you prefer to set up RBAC manually instead of using the script:

Step 1: Grant Namespace Admin

oc create rolebinding spark-demo-admin \
  --clusterrole=admin \
  --user=<username> \
  -n <namespace>

This grants full control over SparkApplications, Pods, Services, Events, LocalQueues, and all other namespace-scoped resources.

Step 2: Grant ClusterQueue Read Access

cat <<EOF | oc apply -f -
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: kueue-cq-viewer
rules:
- apiGroups: ["kueue.x-k8s.io"]
  resources: ["clusterqueues", "resourceflavors"]
  verbs: ["get", "list", "watch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: spark-demo-cq-viewer-<username>
subjects:
- kind: User
  name: <username>
  apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: ClusterRole
  name: kueue-cq-viewer
  apiGroup: rbac.authorization.k8s.io
EOF

This lets the user run oc get clusterqueue to verify quota and admission status.

After Setup — User Workflow

# Log in as the non-admin user
oc login -u user1
oc project spark-kueue-demo

# All test cases work without cluster-admin
oc apply -f tc1-baseline-no-kueue.yaml
oc apply -f tc2-kueue-admission-blocking.yaml
oc apply -f tc4a-large-job.yaml
oc apply -f tc4b-queued-job.yaml
oc apply -f tc5-dynamic-allocation.yaml
oc apply -f tc7-executor-failure.yaml

# Monitor queue status (read-only)
oc get clusterqueue spark-cq
oc get localqueue -n spark-kueue-demo
