Quick Start Guide

Reproduce all 5 demo use cases on your own cluster in under 15 minutes

Prerequisites

  1. OpenShift 4.19+ with RHOAI 3.5 installed
  2. Spark Operator enabled (sparkoperator: Managed in DataScienceCluster)
  3. Red Hat build of Kueue v1.4+ with SparkApplication integration and gang scheduling:
# oc edit kueue cluster -n openshift-kueue-operator
apiVersion: kueue.openshift.io/v1
kind: Kueue
metadata:
  name: cluster
  namespace: openshift-kueue-operator
spec:
  managementState: Managed
  config:
    integrations:
      frameworks:
      - BatchJob
      - sparkoperator.k8s.io/sparkapplication
    gangScheduling:
      policy: ByWorkload
      byWorkload:
        admission: Sequential
Important: Requires RHBoK 1.4+ (Kueue 0.18). RHBoK 1.3 does not include the SparkApplication reconciler.

One-Time Admin Setup

Option A — Automated Script
git clone https://github.com/rrbanda/ai-platforms.git
cd ai-platforms/redhat/rhoai/v3.5/base/03-workloads/spark-kueue-contention-poc

# Creates namespace, ClusterQueues, LocalQueues, and RBAC
./setup-demo-namespace.sh spark-kueue-demo user1

See RBAC page for what the script creates and manual alternatives.

Option B — Use Existing Namespace
# Apply Kueue infrastructure
oc apply -f kueue-resource-flavor.yaml
oc apply -f kueue-cluster-queue.yaml
oc apply -f kueue-local-queue.yaml
oc apply -f networkpolicy.yaml

Verify Setup

oc get clusterqueue spark-cq
oc get localqueue spark-lq -n <namespace>
oc get pods -l app.kubernetes.io/name=spark-operator -n redhat-ods-applications
NAME PENDING WORKLOADS spark-cq 0 NAME CLUSTER QUEUE PENDING WORKLOADS spark-lq spark-cq 0 spark-operator-controller-... 1/1 Running spark-operator-webhook-... 1/1 Running

Run the Test Cases

TC-1: Half-Admitted State (The Problem)

What to look for: driver Running, 3 executors Pending
cat tc1-baseline-no-kueue.yaml    # No Kueue label, 33 CPU total
oc apply -f tc1-baseline-no-kueue.yaml
sleep 15
oc get pods -l sparkoperator.k8s.io/app-name=tc1-baseline-no-kueue -o wide
tc1-baseline-no-kueue-driver 1/1 Running pythonpi-...-exec-1 1/1 Running pythonpi-...-exec-2 0/1 Pending pythonpi-...-exec-3 0/1 Pending pythonpi-...-exec-4 0/1 Pending
oc delete sparkapplication tc1-baseline-no-kueue

TC-2: Kueue Admission Control (The Solution)

What to look for: SUSPENDED, zero pods
cat tc2-kueue-admission-blocking.yaml    # Same job + Kueue label
oc apply -f tc2-kueue-admission-blocking.yaml
sleep 5
oc get sparkapplication tc2-kueue-admission-block
oc get pods -l sparkoperator.k8s.io/app-name=tc2-kueue-admission-block
NAME SUSPEND STATUS tc2-kueue-admission-block true SUSPENDED No resources found in namespace.
oc delete sparkapplication tc2-kueue-admission-block

TC-4: Automatic Queuing & Release

What to look for: Job B auto-admits when Job A completes
# Patch quota to 6 CPU (or use spark-lq-6cpu if setup script was used)
oc patch clusterqueue spark-cq --type merge \
  -p '{"spec":{"resourceGroups":[{"coveredResources":["cpu","memory"],"flavors":[{"name":"default-flavor","resources":[{"name":"cpu","nominalQuota":"6"},{"name":"memory","nominalQuota":"32Gi"}]}]}]}}'

oc apply -f tc4a-large-job.yaml
sleep 3
oc apply -f tc4b-queued-job.yaml
oc get sparkapplication -w
tc4-job-a false RUNNING 1 ... tc4-job-b true SUSPENDED ... tc4-job-a false COMPLETED 1 ... tc4-job-b false RUNNING 1 ... (admitted in ~2 seconds)
oc delete sparkapplication --all --ignore-not-found

TC-5: Dynamic Allocation Rejection

What to look for: immediate webhook rejection
cat tc5-dynamic-allocation.yaml    # dynamicAllocation: true + Kueue label
oc apply -f tc5-dynamic-allocation.yaml
Error from server (Forbidden): admission webhook "vsparkapplication.kb.io" denied the request: a kueue managed job can use dynamicAllocation only when the ElasticJobsViaWorkloadSlices feature gate is on

TC-7: Executor Failure & Recovery

What to look for: exec-4 replaces killed exec-2, job COMPLETED
# Restore quota to 8 CPU
oc patch clusterqueue spark-cq --type merge \
  -p '{"spec":{"resourceGroups":[{"coveredResources":["cpu","memory"],"flavors":[{"name":"default-flavor","resources":[{"name":"cpu","nominalQuota":"8"},{"name":"memory","nominalQuota":"32Gi"}]}]}]}}'

oc apply -f tc7-executor-failure.yaml
oc get pods -l sparkoperator.k8s.io/app-name=tc7-executor-failure -w
# Wait for all 4 pods Running, then Ctrl+C

# Kill an executor
EXEC_POD=$(oc get pods -l sparkoperator.k8s.io/app-name=tc7-executor-failure \
  --no-headers | grep exec-2 | awk '{print $1}')
oc delete pod $EXEC_POD --grace-period=0 --force

# Watch for replacement
oc get pods -l sparkoperator.k8s.io/app-name=tc7-executor-failure -w
pythonpi-...-exec-1 1/1 Running 0 32s pythonpi-...-exec-3 1/1 Running 0 32s pythonpi-...-exec-4 1/1 Running 0 2s ← replacement # After ~3 minutes: oc get sparkapplication tc7-executor-failure # STATUS: COMPLETED, executionAttempts: 1
oc delete sparkapplication --all --ignore-not-found

Troubleshooting

Stale Workloads: If a SparkApplication stays Suspended after deleting and re-creating, check oc get workloads for orphaned Workload objects and delete them manually.
Webhook Not Patched: If TC-5 doesn't reject, verify the Kueue validating webhook covers your namespace: oc get validatingwebhookconfiguration -o yaml | grep namespace
Spark Operator Not Creating Pods: Check that the namespace is labeled for Kueue management: oc get ns <namespace> --show-labels | grep kueue
