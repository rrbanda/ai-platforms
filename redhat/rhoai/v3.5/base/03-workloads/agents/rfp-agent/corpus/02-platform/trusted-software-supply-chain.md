# Red Hat Trusted Software Supply Chain (RHADS-SSC)

## Overview

Red Hat Advanced Developer Suite — Software Supply Chain (RHADS-SSC) is a DevSecOps framework that integrates security from project inception to production. It embeds security checks into CI/CD pipelines, ensures artifact integrity through cryptographic signing, and enforces compliance with Supply chain Levels for Software Artifacts (SLSA) Level 3.

## Core Components

| Component | Function |
|-----------|----------|
| **Red Hat Developer Hub (RHDH)** | Self-service portal with security best practices built in from project creation |
| **Red Hat Trusted Artifact Signer (RHTAS)** | Sigstore-based signing and attestation for artifact integrity |
| **Red Hat Trusted Profile Analyzer (RHTPA)** | Automated SBOM creation and management (Trustify) |
| **Red Hat Advanced Cluster Security (RHACS)** | Artifact vulnerability scanning at build, deploy, and runtime |
| **Red Hat Quay** | Security-enhanced container registry with continuous scanning |
| **OpenShift Pipelines (Tekton)** | Automated CI/CD with Tekton Chains for provenance |
| **Conforma** | Policy-as-code validation gates (formerly Enterprise Contract) |

## SLSA Level 3 Compliance

Every build pipeline produces:

1. **Signed in-toto attestation**: Cryptographically verifies the build's integrity and process
2. **SLSA provenance**: Tamper-proof record of build process details
3. **Software Bill of Materials (SBOM)**: CycloneDX or SPDX format documenting all components
4. **Image signatures**: Cosign signatures stored in OCI registry
5. **Vulnerability scan results**: RHACS scanning at build time

### What SLSA Level 3 Guarantees

- Build process is defined in code and cannot be modified by individual developers
- Build outputs are cryptographically linked to their source inputs
- Provenance is non-falsifiable (generated by the build system, not the developer)
- Build isolation prevents cross-contamination between builds

## Tekton Chains — Automated Supply Chain Security

Tekton Chains is a Kubernetes CRD controller that observes all pipeline executions:

1. **Observes**: Watches all task run executions in the cluster
2. **Snapshots**: Captures task run state on completion
3. **Converts**: Transforms snapshot to standard payload formats (in-toto, SLSA)
4. **Signs**: Cryptographically signs all artifacts using Cosign
5. **Stores**: Persists signatures and attestations in OCI repository

This happens automatically with zero developer intervention after initial configuration.

## Security Gates & Policy Enforcement

### Conforma (Policy Validation)

Conforma evaluates builds against defined policies before production deployment:

- 41+ built-in rules for container image security
- Validates SLSA requirements compliance
- Checks for prohibited components (e.g., "No log4j allowed", no `curl`/`wget` in production images)
- Verifies image signatures and attestation chains
- Custom policy definition support for organizational requirements

### RHACS Admission Control

- Blocks unsigned or non-compliant images from deploying
- Enforces base image requirements (must use approved UBI base)
- Validates that vulnerability scans are current
- Checks image provenance chain is intact

## Red Hat Hardened Images & Trusted Libraries

### Hardened Base Images

Red Hat provides production-ready container images with:
- Smaller attack surface (minimal packages)
- Continuous vulnerability remediation by Red Hat
- SBOM included for every image
- SLSA Level 3 provenance

### Trusted Libraries (Python)

Curated Python packages built on SLSA Level 3 infrastructure:
- Cryptographic signatures for every package
- SBOM documenting all transitive dependencies
- Built in isolated, reproducible environments
- Vulnerability monitoring and proactive patching

RHADS-SSC includes AI-driven exploit intelligence:

- Prioritizes remediation based on real-world risk, not just volume of findings
- Intelligent rebuilds triggered when base image vulnerabilities are patched
- Automated pull request workflows for dependency updates
- Continuous developer-friendly remediation process

## Applicability to Vulnerability Remediation Engagements

For organizations with supply chain security findings (Wave 4 in typical remediation programs):

| Finding Type | RHADS-SSC Solution |
|-------------|-------------------|
| **Unsigned artifacts in production** | Tekton Chains + Sigstore automatic signing |
| **No SBOM for deployed applications** | Automated SBOM generation at build time |
| **Vulnerable dependencies** | RHACS scanning + automated PR for updates |
| **No provenance tracking** | SLSA Level 3 attestation for every build |
| **Untrusted base images** | Red Hat Hardened Images with continuous patching |
| **JDK/FOSS version drift** | Trusted Libraries + automated upgrade pipelines |
| **No build isolation** | Hermetic builds (Hermeto) prevent contamination |
| **Policy violations reaching production** | Conforma gates enforce compliance before deploy |
